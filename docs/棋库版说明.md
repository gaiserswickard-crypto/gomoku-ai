## 为什么无需塞入整份压缩包

原谱前三手为 H8、H9、I9。白4在 I8 的分支，经 `r12 = c15 - 2, c12 = r15 - 1` 映射，正好得到课程的四子初盘：黑 `(5,6)、(6,5)`，白 `(5,5)、(6,6)`。

全库有 1,371,455 个节点，相关四子子树只有 334,269 个节点。提取此分支后，剪掉源谱中重复落子的子树、12×12 范围之外的子树，并在已经成五时终止后续线路，最终包含虚拟根在内为 **325,779 个节点**。

每个节点按前序存储“一个落点字节＋变长子节点数”。原始数据共 **651,558 字节**，Base85 文本 **814,450 字节**。加上搜索、查询、校验及字符串语法后，完整源码约 **838.5 KiB**，余量 **189,998 字节**。无需 LZMA，也无需比赛时访问磁盘或网络。

`tools/build_book.py` 保留了生成过程；`results/book/build_report.json` 记录体积和校验和。阅读或修改搜索算法可看 `src/engine.cpp`，查询模块在 `tools/book_runtime.inc`。重新生成与编译：

```powershell
python tools/build_book.py --output main.cpp
.\build.bat
.\tools\test_windows.bat
python tests/protocol_test.py --engine build/gomoku.exe
```

生成会覆盖 `main.cpp` 的手动改动，因此应修改相应基底或生成器，然后重新运行测试。

## 棋库怎样参与选点

1. 搜索引擎先处理立即取胜、必须堵住的胜点和己方立即双胜点。
2. 执黑时按完整棋盘查询走法树，同时核对颜色和棋子总数。支持不同次序到达同一局面，以及保持全盘边界和颜色的四个对称变换。查询不用概率哈希判断是否命中。
3. 对棋谱建议检查能否应对现成的双威胁，并用短时 VCF 搜索排除已被证明会让对手连续冲四获胜的点。未找到反驳仅表示未知。
4. 未收录、数据损坏、查询超过预算或建议全部被排除时，继续 v2 搜索。执白也继续使用搜索。

运行时解码会再次检查前序树结构、路径重复、坐标范围、深度和节点数。源码内的数据只解码一次，不在每步重复解压。

## 验证发现与实际结果

全库解析发现 427 处重复落子，相关子树受影响的节点连同后代为 120 个。两种独立的结构解析对全部父节点关系进行了比较，结果一致，排除了兄弟回溯解释错误。导入时将这些无效分支剔除。

对最终走法树的独立 12×12 规则审计没有发现越界、重复落子或成五后继续走的路径，但发现 7 个黑方建议漏堵唯一胜点、71 个建议没有直接取现成胜点。运行时的立即战术优先级会覆盖这些建议；集成测试采用其中的真实局面验证这一点。

此外，大量白方合法应手没有列在树内，105,552 个叶子没有被本次审计直接证明为终局或立即胜形，另有 2 个叶子是白方成五。该棋谱不能直接作为完整的黑方必胜证明；剪掉越界线路也不等于证明剩余策略对 12×12 仍然必胜。原始审计见 `results/book/independent_audit.json`。

七套 C++ 测试及九项协议测试全部通过。测试包括原战术与随机规则校验、实际平台败局、双威胁防守、对称去重，以及新增的棋库精确匹配、非法数据、错误颜色、额外棋子、换序、回退和错误推荐覆盖。

同一源码的调试构建与两个对手重新换色对弈，调试信息只写标准错误，用于统计棋库选点：

| 对手 | 棋库版执黑 | 棋库版执白 | 黑方棋库选点次数 |
| --- | --- | --- | ---: |
| v2 | 胜，29 手 | 负，25 手 | 8 |
| 往年参考程序 | 胜，25 手 | 负，31 手 | 7 |

手数为预置四子后双方合计落子数。四局均无超时或非法落子判负，棋库版最长单步约 1.142 秒。两盘黑方胜局的己方总耗时（含启动）约 0.021 秒、0.029 秒，说明这些线路确实主要通过棋库选点，再由搜索完成杀棋。白方没有启用棋库，依然是短板。

正式构建另外通过全部协议测试。启动抽测约 0.019 秒，第一次落子（含棋库加载）约 0.004 秒；截至该步的峰值工作集约 31.6 MiB。该内存抽测不代表对所有完整对局的峰值监控。报告分别为 `results/book/vs_v2.json`、`vs_reference.json`、`resources.json` 和 `validation.json`。

当前实测环境仍是 Windows/MSVC `/O2`。学校 Linux/G++ 编译和真实同学的应对需在平台复测。这四局属于小样本固定开局对战，不能换算为全班胜率，更不能从两个黑方胜局推出“执黑必胜”。
