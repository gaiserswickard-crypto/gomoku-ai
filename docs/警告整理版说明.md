# v4 警告整理版与原版对照

验证日期：2026-11-10。整理版单文件为 `main_warning_clean.cpp`，可直接作为课程源码提交；`main.cpp` 和 `build/gomoku.exe` 仍是原实战版。本次没有代为向学校平台提交。

整理版使用同一份 Rapfi 搜索和官方经典评估模型，源码 **426,088 字节**，低于 1,048,576 字节限制。运行时无需其它文件。本地可执行文件为 `build/gomoku_warning_clean.exe`。

## 修改与编译

新增括号均保持原 C++ 优先级；数量标记从棋形枚举中移出后仍保留同一类型和值。`Pattern2x` 仍为 1 字节，置换表条目仍为 12 字节，桶仍为 64 字节，并以静态断言固定布局。结构体和搜索临时变量显式初始化；无用参数省略名字；可选策略缓冲区以本次调用的构造条件保护读取。未修改评估参数、搜索参数或课程时间预算。

本地 Windows GCC 16.2.0 使用 `-std=c++17 -O2 -Wall -Wextra -Wpedantic -Werror` 编译，诊断日志为 **0 字节**。没有加入全局关闭警告的指令。MSVC C++17 编译及 START/TURN/END 冒烟检查也通过；零警告结论针对记录中的 GCC 编译参数。

## 搜索是否发生变化

从之前的完整对局提取非终局局面，再加入固定种子的合法随机局面，共 **32 个局面**（黑方行棋 20 个、白方行棋 12 个）。两版均关闭墙钟截止，设定最大深度 **14**、节点上限 **100,000**，每个局面清空置换表，在同一个逻辑 CPU 上交替运行 **4 轮**。

全部 **128 组新旧对照**一致：最佳走法、静态评分、搜索评分、主变化路线、已完成深度、搜索节点数、根节点信息及棋盘状态校验值均相同。棋形表、评估表和主要结构尺寸的校验结果也一致。每版每轮累计搜索 **846,680 个节点**，其中 31 个局面实际展开了搜索。

整理版还通过 **1,588 项断言、106 次战术/状态搜索、9/9 组协议检查**。测试包括双方颜色、旋转镜像、长连、连续冲四、活三防守、重置、满盘及搜索状态恢复。

这些证据支持“本次整理没有发现搜索决策或速度退化”。它们不是所有局面完全等价的形式证明，也不能保证未来每一局的走法或胜负完全相同。限时搜索仍可能因硬件、系统负载和编译器不同而停在不同深度。整理版尚未在学校 Linux 环境实测。

## 复现

在项目根目录运行：

```text
python tools/build_rapfi.py --model trained --clean-warnings
```

生成结果为 `rapfi_port/rapfi_warning_clean.cpp`，与交付的 `main_warning_clean.cpp` 字节相同。不带 `--clean-warnings` 时仍能复现原 v4 的源码。

严格编译（Linux 的目标命令，尚未在 Linux 执行）：

```text
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic -Werror main_warning_clean.cpp -o gomoku_warning_clean
```

Windows MinGW 链接时增加 `-Wl,--stack,8388608`；本地编译器路径为 `tmp/rapfi_tools/w64devkit/bin/g++.exe`。对照复现入口：

```text
python tools/compare_rapfi_warnings.py --depth 14 --nodes 100000 --rounds 4
```
